# 一、本阶段目标

本阶段只实现 Git 基础能力，为后续 Commit Message、风险检查和周报生成提供可靠的数据来源。

需要完成以下数据流程：

```text
识别当前 Git 仓库
    ↓
读取仓库基础信息
    ↓
读取暂存区或工作区 Diff
    ↓
解析文件状态与变更统计
    ↓
过滤不需要分析的文件
    ↓
限制单文件及总 Diff 大小
    ↓
读取指定日期范围的 Git Log
    ↓
输出结构化 Git 数据
```

本阶段不得实现：

* 真实 AI 模型调用
* Commit Message 生成
* AI 提交拆分判断
* 敏感信息扫描
* SQLite 业务存储
* Worklog 完整功能
* 周报 AI 聚合
* 飞书机器人发送
* Web 页面
* 自动执行 Git Commit
* 自动修改暂存区

# 四、Git 命令执行器

实现统一的 Git 命令执行组件，避免每个模块重复调用 `subprocess`。

建议接口：

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Sequence


@dataclass(frozen=True)
class GitCommandResult:
    command: tuple[str, ...]
    return_code: int
    stdout: str
    stderr: str


class GitCommandRunner:
    def __init__(
        self,
        working_directory: Path,
        timeout_seconds: float = 10.0,
    ) -> None:
        ...

    def run(
        self,
        arguments: Sequence[str],
        *,
        check: bool = True,
    ) -> GitCommandResult:
        ...
```

调用方式必须使用参数数组：

```python
subprocess.run(
    ["git", "status", "--porcelain"],
    cwd=working_directory,
    capture_output=True,
    text=True,
    timeout=timeout_seconds,
    check=False,
)
```

禁止：

```python
shell=True
```

禁止拼接字符串执行：

```python
subprocess.run(f"git show {commit}", shell=True)
```

必须考虑：

* 路径中包含空格
* Git 命令不存在
* 当前目录不存在
* 命令超时
* Git 返回非零退出码
* stdout 编码问题
* stderr 为空
* 用户传入非法 Commit 参数
* Windows、Linux 和 macOS 的路径兼容性

定义或复用以下异常：

```text
GitPulseError
GitRepositoryError
GitCommandError
GitCommandTimeoutError
GitParseError
```

错误消息中应包含：

* 执行的 Git 子命令
* 工作目录
* 返回码
* 可安全展示的错误信息

不要在异常中输出敏感环境变量。

需要正确处理：

## 1. 当前目录不是 Git 仓库

抛出友好异常：

```text
当前目录不是 Git 仓库。

请进入 Git 项目目录后重新执行，
或运行：

git init
```

## 2. 空仓库

仓库已经执行 `git init`，但没有任何 Commit 时：

* `is_repository()` 返回 `True`
* `get_root()` 正常返回
* `get_head_commit()` 返回 `None`
* 不应把空仓库误判为非 Git 仓库

## 3. Detached HEAD

当仓库处于 detached HEAD 状态：

* `get_current_branch()` 可以返回 `None`
* 或返回明确的 detached 状态模型
* 不得抛出无法理解的底层 Git 错误

## 4. Git 用户未配置

`get_user_name()` 和 `get_user_email()` 返回 `None`。

不得在仓库基础信息读取阶段强制失败。

后续需要作者筛选时，再提示用户进行配置。

解析：

```bash

```

```python
from enum import StrEnum
from pydantic import BaseModel


class GitFileStatus(StrEnum):
    ADDED = "A"
    MODIFIED = "M"
    DELETED = "D"
    RENAMED = "R"
    COPIED = "C"
    UNMERGED = "U"
    UNTRACKED = "?"

    worktree_status: str
    path: str
```

```text

A  src/new.py
D  src/old.py
```

1. 文件路径可能包含空格。
2. 重命名可能包含旧路径和新路径。

5. 测试必须覆盖中文路径和带空格路径。

# 八、Diff 数据模型

在 `models/diff.py` 中实现结构化模型。

参考：

```python
from enum import StrEnum
from pydantic import BaseModel, Field


class FileChangeStatus(StrEnum):
    ADDED = "A"
    MODIFIED = "M"
    DELETED = "D"
    RENAMED = "R"
    COPIED = "C"
    UNMERGED = "U"
    UNKNOWN = "UNKNOWN"


class DiffSource(StrEnum):
    STAGED = "staged"
    UNSTAGED = "unstaged"
    COMMIT = "commit"
    RANGE = "range"


class FileDiff(BaseModel):
    old_path: str | None = None
    new_path: str
    status: FileChangeStatus
    additions: int = 0
    deletions: int = 0
    patch: str = ""
    extension: str | None = None
    is_binary: bool = False
    is_new_file: bool = False
    is_deleted_file: bool = False
    is_renamed: bool = False
    is_copied: bool = False
    is_truncated: bool = False
    original_patch_chars: int = 0


class DiffStats(BaseModel):
    files_changed: int = 0
    insertions: int = 0
    deletions: int = 0
    total_patch_chars: int = 0


class DiffCollection(BaseModel):
    source: DiffSource
    base_commit: str | None = None
    target_commit: str | None = None
    files: list[FileDiff] = Field(default_factory=list)
    stats: DiffStats = Field(default_factory=DiffStats)
    ignored_files: list[str] = Field(default_factory=list)
    truncated_files: list[str] = Field(default_factory=list)
    original_total_chars: int = 0
    final_total_chars: int = 0
```

* 文件路径
* 文件状态
* 新增行数
* 删除行数
* Patch
* 文件扩展名
* 是否二进制
* 是否新增
* 是否删除
* 是否重命名
* 是否复制
* 是否被截断
* 忽略文件列表
* 截断文件列表
* 原始总长度
* 最终总长度

# 十、Diff Parser

在 `parser.py` 中实现 Git Patch 解析。

需要识别常见头部：

```text
diff --git a/src/main.py b/src/main.py
index abc1234..def5678 100644
--- a/src/main.py
+++ b/src/main.py
@@ -1,3 +1,4 @@
```

新增文件：

```text
new file mode 100644
--- /dev/null
+++ b/src/new.py
```

删除文件：

```text
deleted file mode 100644
--- a/src/old.py
+++ /dev/null
```

重命名：

```text
similarity index 98%
rename from old_name.py
rename to new_name.py
```

复制：

```text
copy from source.py
copy to target.py
```

二进制：

```text
Binary files a/image.png and b/image.png differ
```

或：

```text
GIT binary patch
```

要求：

1. 每个 `diff --git` 块解析为一个 `FileDiff`。
2. 路径前缀 `a/`、`b/` 应正确处理。
3. 保留原始相对路径。
4. 不要错误删除文件名中的 `a/` 或 `b/` 字符。
5. 支持无扩展名文件。
6. 支持多后缀文件，如 `.tar.gz`。
7. 二进制文件的 `patch` 可以只保留安全摘要。
8. 解析失败时提供明确错误，但尽可能保留已解析文件。
9. 测试覆盖新增、修改、删除、重命名、复制和二进制文件。

# 十一、文件过滤

根据 `.gitpulse.yml` 的配置实现文件过滤。

```python
class DiffConfig(BaseModel):

    max_file_chars: int = 15000
    ignore_binary: bool = True
    ignore_patterns: list[str] = [
        "*.lock",
        "dist/**",
        "build/**",
        "node_modules/**",
        "*.min.js",
    ]
```

匹配时需要考虑：

* POSIX 相对路径
* Windows 路径分隔符
* 文件名模式
* 目录递归模式
* 中文路径
* 大小写行为应明确
* 不允许模式逃逸仓库根目录

建议统一将 Git 相对路径转换为 `/` 分隔符后匹配。

需要提供：

```python
class FileFilter:
    def should_ignore(self, path: str, is_binary: bool) -> bool:
        ...
```

规则：

1. `ignore_binary=true` 时忽略二进制内容。
2. 被忽略文件仍应记录在 `ignored_files`。
3. 文件统计是否包含被忽略文件，需要明确设计。
4. 推荐原始 Git 统计保留全部文件，AI 输入统计另行提供过滤后结果。
5. 不得静默丢弃文件。
6. 忽略行为要有可追踪原因。

可以把忽略记录设计为：

```python
class IgnoredFile(BaseModel):
    path: str
    reason: str
```

# 十二、Diff 截断

实现两个限制：

```yaml
diff:
  max_total_chars: 60000
  max_file_chars: 15000
```

建议类：

```python
class DiffTruncator:
    def truncate(
        self,
        collection: DiffCollection,
    ) -> DiffCollection:
        ...
```

截断规则：

## 单文件截断

当某个文件 Patch 超过 `max_file_chars`：

1. 保留文件头部信息。
2. 保留部分修改区块。
3. 标记 `is_truncated=true`。
4. 保存 `original_patch_chars`。
5. 在 Patch 末尾增加明确标记：

```text
[GitPulse: 当前文件 Diff 已截断]
```

## 总长度截断

当所有文件 Patch 总长度超过 `max_total_chars`：

优先顺序建议：

1. 保留非二进制文件。
2. 保留未被忽略文件。
3. 保留较小且完整的文件。
4. 保留核心代码文件。
5. 最后截断超大文件。

不要擅自根据文件名判断业务价值。

可以按以下稳定规则处理：

* 首先对每个文件执行单文件截断
* 然后按照 Git 返回顺序累加
* 超过总限制后停止加入完整 Patch
* 后续文件保留元数据，但 Patch 为空或仅含截断说明

必须记录：

```text
original_total_chars
final_total_chars
truncated_files
ignored_files
```

如果 `max_total_chars <= 0` 或 `max_file_chars <= 0`，配置校验应失败。

# 十三、Git Log Reader

在 `log_reader.py` 中实现指定日期范围和作者的提交读取。

建议接口：

```python
from datetime import datetime


class GitLogReader:
    def __init__(self, repository: GitRepository) -> None:
        ...

    def read(
        self,
        date_from: datetime,
        date_to: datetime,
        *,
        authors: list[str] | None = None,
        branches: list[str] | None = None,
        max_count: int = 200,
    ) -> list["GitCommitRecord"]:
        ...
```

定义模型：

```python
from datetime import datetime
from pydantic import BaseModel, Field


class GitCommitRecord(BaseModel):
    commit_hash: str
    short_hash: str
    author_name: str
    author_email: str
    authored_at: datetime
    committed_at: datetime
    subject: str
    body: str = ""
    parents: list[str] = Field(default_factory=list)
    changed_files: list[str] = Field(default_factory=list)
    insertions: int = 0
    deletions: int = 0
```

推荐使用自定义格式和空字符分隔，避免 Commit Message 中出现换行或分隔符导致解析错误。

例如研究使用：

```bash
git log \
  --since=<date> \
  --until=<date> \
  --format=<custom-format> \
  -z
```

必须支持：

* 单个作者邮箱
* 多个作者邮箱
* 不传作者时读取全部作者
* 自然周日期范围
* 包含时区的时间
* 最多读取 200 个 Commit
* 合并提交
* 空 Commit
* 中文 Commit Message
* 多行 Commit Body

作者筛选优先以邮箱为准。

如果多个邮箱需要组合，而 Git `--author` 行为不够稳定，可以：

1. 读取日期范围内 Commit。
2. 在 Python 中按精确邮箱过滤。

需要明确是否包含 Merge Commit。

MVP 建议默认包含，但模型中标记父 Commit 数量，方便后续周报逻辑决定是否使用。

# 十七、质量要求

代码必须满足：

1. 所有公共函数具有类型注解。
2. 核心类具有必要的文档字符串。
3. 不使用 `shell=True`。
4. 不在 CLI 中直接解析 Diff。
5. 不在 Service 层直接操作 subprocess。
6. 不静默忽略 Git 错误。
7. 不修改 Git 仓库状态。
8. 不调用 `git add`、`git commit`、`git reset`、`git restore` 或 `git push`。
9. Git 读取操作尽量使用只读命令。
10. 所有路径使用 `pathlib.Path`。
11. 对 Git 返回的仓库内路径统一为 POSIX 格式。
12. 不使用可变对象作为默认参数。
13. 避免超长函数。
14. 解析逻辑和命令执行逻辑分离。
15. 测试中不得依赖真实远程仓库。
