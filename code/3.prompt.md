# 一、本阶段目标

本阶段实现 GitPulse 的安全与隐私预处理能力。

完整处理流程：

```text
读取结构化 Diff
    ↓
识别敏感信息
    ↓
识别隐私信息
    ↓
生成风险记录
    ↓
按风险等级分类
    ↓
对允许处理的内容进行脱敏
    ↓
判断是否允许调用远程模型
    ↓
生成安全的 AI 输入
```

本阶段重点完成：

1. 敏感信息规则扫描
2. 私钥和凭证检测
3. 数据库连接字符串检测
4. 内网信息检测
5. 本地路径与用户名脱敏
6. 邮箱和手机号脱敏
7. 风险等级分类
8. 高风险内容阻断
9. 扫描结果结构化
10. 安全扫描 CLI 接入
11. 单元测试与集成测试

本阶段暂不实现：

* 真实 AI 模型调用
* Commit Message 生成
* AI 多主题判断
* SQLite 业务存储
* Worklog 完整功能
* 周报生成
* 飞书机器人发送
* Web 页面
* 自动修改 Git 暂存区
* 自动删除敏感内容
* 自动替换源代码文件内容

安全模块只分析内存中的 Diff 内容，不得修改用户文件。

# 四、安全设计原则

实现过程中必须遵循：

1. 默认不信任输入内容。
2. 扫描失败时默认视为不安全。
3. 高风险内容默认阻止远程模型调用。
4. 严重风险内容不得进入远程 AI 请求。
5. 原始敏感值不得写入日志。
6. 原始敏感值不得出现在异常消息中。
7. 原始敏感值不得保存到测试快照。
8. 脱敏映射只保存在当前本地进程或本地安全存储中。
9. 脱敏映射不得发送给远程模型。
10. 扫描模块不得修改源文件。
11. 扫描模块不得自动执行 Git 命令。
12. 正则检测结果只代表风险提示，不代表绝对确认。
13. 对高召回规则应允许出现一定误报。
14. 风险报告必须提供安全的定位信息。
15. 所有规则必须可扩展、可单独关闭和单独测试。

# 五、安全配置模型

在 `.gitpulse.yml` 中完善安全配置。

建议配置：

```yaml
security:
  enabled: true
  scan_secrets: true
  scan_personal_information: true
  scan_internal_network: true
  block_remote_on_high_risk: true
  block_remote_on_scan_failure: true
  mask_local_paths: true
  mask_user_names: true
  mask_emails: true
  mask_internal_domains: true
  mask_private_ips: true
  mask_phone_numbers: true
  keep_last_chars: 4
  entropy_detection: false
  max_findings_per_rule: 100
  ignored_rules: []
  custom_patterns: []
```

使用 Pydantic 定义：

```python
from pydantic import BaseModel, Field, field_validator


class CustomSecurityPattern(BaseModel):
    id: str
    name: str
    pattern: str
    level: str
    description: str
    replacement: str = "<MASKED>"


class SecurityConfig(BaseModel):
    enabled: bool = True
    scan_secrets: bool = True
    scan_personal_information: bool = True
    scan_internal_network: bool = True
    block_remote_on_high_risk: bool = True
    block_remote_on_scan_failure: bool = True
    mask_local_paths: bool = True
    mask_user_names: bool = True
    mask_emails: bool = True
    mask_internal_domains: bool = True
    mask_private_ips: bool = True
    mask_phone_numbers: bool = True
    keep_last_chars: int = 4
    entropy_detection: bool = False
    max_findings_per_rule: int = 100
    ignored_rules: list[str] = Field(default_factory=list)
    custom_patterns: list[CustomSecurityPattern] = Field(
        default_factory=list
    )
```

配置校验要求：

* `keep_last_chars` 必须在 0 至 12 之间
* `max_findings_per_rule` 必须大于 0
* 自定义规则 ID 不得重复
* 自定义正则必须能成功编译
* 风险等级必须是合法值
* 禁止空正则表达式
* 禁止能够匹配空字符串的自定义正则
* 配置错误时指出具体字段和修复方式

风险等级：

```text
low
medium
high
critical
```

# 六、风险数据模型

在 `models/risk.py` 中实现风险模型。

参考设计：

```python
from enum import StrEnum
from pydantic import BaseModel, Field


class RiskLevel(StrEnum):
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"
    CRITICAL = "critical"


class RiskCategory(StrEnum):
    SECRET = "secret"
    CREDENTIAL = "credential"
    PRIVATE_KEY = "private_key"
    DATABASE_URL = "database_url"
    INTERNAL_NETWORK = "internal_network"
    PERSONAL_INFORMATION = "personal_information"
    LOCAL_PATH = "local_path"
    USER_NAME = "user_name"
    DEBUG_CONTENT = "debug_content"
    CONFIGURATION = "configuration"
    UNKNOWN = "unknown"


class SecurityFinding(BaseModel):
    id: str
    rule_id: str
    rule_name: str
    category: RiskCategory
    level: RiskLevel
    file_path: str | None = None
    line_number: int | None = None
    column_start: int | None = None
    column_end: int | None = None
    description: str
    masked_value: str | None = None
    suggestion: str | None = None
    confidence: float = 1.0
    blocks_remote_model: bool = False
```

扫描汇总模型：

```python
class SecurityScanSummary(BaseModel):
    low: int = 0
    medium: int = 0
    high: int = 0
    critical: int = 0
    files_scanned: int = 0
    files_with_findings: int = 0
    total_findings: int = 0


class SecurityScanResult(BaseModel):
    passed: bool
    scan_completed: bool
    block_remote_model: bool
    summary: SecurityScanSummary
    findings: list[SecurityFinding] = Field(default_factory=list)
    sanitized_diff: str = ""
    masked_diff_collection: object | None = None
    warnings: list[str] = Field(default_factory=list)
    errors: list[str] = Field(default_factory=list)
```

实际类型中不要使用 `object`，应引用第二阶段已经实现的 `DiffCollection`。

如果存在循环引用，应合理拆分模块或使用延迟类型引用。

# 七、安全规则模型

实现统一规则模型。

建议：

```python
from dataclasses import dataclass
from re import Pattern


@dataclass(frozen=True)
class SecurityRule:
    id: str
    name: str
    pattern: Pattern[str]
    category: RiskCategory
    level: RiskLevel
    description: str
    suggestion: str
    replacement: str
    blocks_remote_model: bool
    enabled_by_default: bool = True
    confidence: float = 1.0
```

要求：

1. 所有内置规则拥有稳定唯一 ID。
2. ID 应使用小写英文和下划线。
3. 规则注册集中管理。
4. 不要把所有正则散落在业务代码中。
5. 每条规则必须拥有单独测试。
6. 自定义规则和内置规则使用相同扫描流程。
7. 用户可通过 `ignored_rules` 禁用指定规则。
8. 规则命中数量超过限制时停止继续记录，但保留告警。
9. 规则不得在导入模块时读取用户环境变量。
10. 规则不得匹配空字符串。

# 八、必须支持的敏感信息规则

至少实现以下规则。

## 1. OpenAI 风格 API Key

检测类似：

```text
sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

要求：

* 避免把普通短字符串误判为 Key
* 输出时仅显示开头、掩码和末尾少量字符
* 风险等级为 high
* 阻止远程模型调用

---

## 2. GitHub Token

至少覆盖常见前缀：

```text
ghp_
github_pat_
gho_
ghu_
ghs_
ghr_
```

风险等级：

```text
high
```

阻止远程模型调用。

---

## 3. GitLab Token

覆盖类似：

```text
glpat-
```

风险等级：

```text
high
```

---

## 4. AWS Access Key

检测类似：

```text
AKIA...
ASIA...
```

单独检测 Access Key ID 时可以标记为 high。

如果同时发现疑似 Secret Access Key，应标记为 critical 或 high。

不得在报告中显示完整值。

---

## 5. Bearer Token

检测：

```text
Authorization: Bearer ...
```

或：

```text
Bearer eyJ...
```

风险等级：

```text
high
```

注意避免将示例文本中的短占位符误判。

---

## 6. JWT

识别由三个 Base64URL 片段组成的 JWT。

例如：

```text
xxxxx.yyyyy.zzzzz
```

要求：

* 每一段达到合理最小长度
* 避免匹配版本号或普通文件名
* 风险等级为 high
* 阻止远程调用

---

## 7. 通用密码字段

检测类似：

```text
password = "..."
passwd: "..."
pwd = "..."
```

需要区分：

```text
password = os.getenv("PASSWORD")
```

这种没有直接硬编码秘密值的情况。

建议：

* 明确硬编码值：high
* 环境变量引用：不报告或仅 low 提示
* 占位符如 `your_password`：medium 或忽略

不得只因为出现单词 `password` 就判定为秘密泄露。

---

## 8. 通用 Secret 和 Token 字段

检测：

```text
secret = "..."
token = "..."
api_key = "..."
access_key = "..."
client_secret = "..."
```

同样需要区分硬编码和环境变量引用。

必须检测：

```text
-----BEGIN EC PRIVATE KEY-----
```


# 九、熵检测

配置中预留：

```yaml
security:
  entropy_detection: false
```

MVP 阶段默认关闭。

如果实现简单熵检测，需要满足：

1. 只扫描达到最小长度的字符串。
2. 排除自然语言文本。
3. 排除常见 Hash。
4. 排除 UUID。
5. 排除 Git Commit Hash。
6. 排除 Base64 图片片段。
7. 将结果标记为 medium，而不是直接 critical。
8. 只作为补充规则。
9. 必须有大量误报测试。
10. 不得因熵检测结果单独阻止远程模型，除非用户配置明确要求。

如果无法稳定实现，可以仅保留接口和配置，不必在第三阶段启用。

# 十、Secret Scanner

在 `secret_scanner.py` 中实现扫描器。

建议接口：

```python
class SecretScanner:
    def __init__(
        self,
        rules: list[SecurityRule],
        config: SecurityConfig,
    ) -> None:
        ...

    def scan_text(
        self,
        text: str,
        *,
        file_path: str | None = None,
    ) -> list[SecurityFinding]:
        ...

    def scan_file_diff(
        self,
        file_diff: FileDiff,
    ) -> list[SecurityFinding]:
        ...

    def scan_collection(
        self,
        collection: DiffCollection,
    ) -> SecurityScanResult:
        ...
```

要求：

1. 支持多行正则。
2. 正确计算行号。
3. 尽量提供列号。
4. 不记录完整命中值。
5. 不允许正则灾难性回溯影响 CLI。
6. 对单规则命中数量设置限制。
7. 同一位置重复命中相似规则时进行去重。
8. 风险排序按照：

   * critical
   * high
   * medium
   * low
9. 同等级按文件和行号排序。
10. 二进制文件不扫描原始内容。
11. 被忽略文件不扫描 Patch 内容，但可以在结果中保留“已忽略”状态。
12. 截断 Diff 只能扫描可见部分，并增加警告。
13. 扫描结果必须说明扫描覆盖范围。

# 十一、行号定位

Diff 中的行号不是简单的 Patch 文本行号。

实现时至少区分：

```text
patch_line_number
source_line_number
target_line_number
```

如果第三阶段不实现完整 Hunk 行号映射，至少保证：

* `line_number` 表示 Patch 中的行号
* 字段命名不要误导为源文件真实行号
* 输出提示中明确说明是 Diff 行号

更推荐扩展模型：

```python
class SecurityLocation(BaseModel):
    patch_line: int | None = None
    old_file_line: int | None = None
    new_file_line: int | None = None
```

扫描新增代码时优先记录 `new_file_line`。

扫描删除代码时可以选择：

* 默认不扫描删除行
* 或扫描但标记为已删除内容

建议 MVP 默认：

```text
扫描新增行和上下文行
忽略删除行中的敏感信息阻断
```

原因是删除掉的秘密不一定会进入新 Commit 内容，但需要注意：

如果秘密此前已经提交过，应提示用户检查 Git 历史。

可以生成：

```text
检测到被删除的疑似凭证，请确认该凭证是否曾经进入 Git 历史。
```

该提示可以是 medium 或 high，但是否阻断当前远程调用应根据最终发送内容决定。

```python
        ...
```

数据模型：

```python
class MaskMapping(BaseModel):
    placeholder: str
    category: str
    masked_value: str
    occurrence_count: int = 1


class MaskingResult(BaseModel):
    original_length: int
    masked_length: int
    masked_text: str
    mappings: list[MaskMapping]
```

注意：

`MaskMapping` 不得保存完整原始秘密值。

如果为了本地恢复确实需要映射原始值：

* 必须使用单独的私有模型
* 不得写入普通日志
* 不得包含在返回给 AI 的对象中
* 不得序列化进远程请求
* 测试输出不得展示完整值

# 十三、脱敏规则

## 1. 占位符稳定性

相同值在同一次扫描中应映射到相同占位符。

例如：

```text
10.10.1.8
```

多次出现时统一替换为：

```text
<PRIVATE_IP_1>
```

不同值：

```text
<PRIVATE_IP_1>
<PRIVATE_IP_2>
```

---

## 2. 占位符分类

建议：

```text
<API_KEY_1>
<ACCESS_TOKEN_1>
<PRIVATE_KEY>
<DATABASE_URL_1>
<PRIVATE_IP_1>
<INTERNAL_DOMAIN_1>
<EMAIL_1>
<PHONE_1>
<ID_CARD_1>
<USER_HOME>
<LOCAL_PATH_1>
<USER_NAME_1>
```

---

## 3. 结构保留

脱敏后尽量保留原始代码结构。

例如：

原始：

```python
DATABASE_URL = "postgresql://admin:secret@10.0.0.8/app"
```

脱敏后：

```python
DATABASE_URL = "<DATABASE_URL_1>"
```

或者：

```python
DATABASE_URL = "postgresql://<DB_USER>:****@<PRIVATE_IP_1>/app"
```

优先选择不破坏 AI 理解代码结构的方式。

---

## 4. 高风险 Secret

对于 API Key、Token、密码和私钥：

* 不只保留尾号后继续传给模型
* 应完整替换为占位符
* `masked_value` 可以用于本地提示
* AI 输入不得包含可恢复信息

---

## 5. 本地路径

原始：

```text
/home/alice/projects/device-manager/src/main.py
```

脱敏：

```text
<USER_HOME>/projects/device-manager/src/main.py
```

应尽量保留仓库内相对路径。

如果 Diff 已经使用仓库相对路径，不要无意义替换。

---

## 6. 邮箱

原始：

```text
alice@company.com
```

可脱敏为：

```text
<EMAIL_1>
```

如果模型需要判断同一作者，可对相同邮箱使用稳定占位符。

---

# 十四、风险分类器

在 `risk_classifier.py` 中实现统一分类逻辑。

建议：

```python
class RiskClassifier:
    def should_block_remote(
        self,
        findings: list[SecurityFinding],
        *,
        scan_completed: bool,
    ) -> bool:
        ...

    def summarize(
        self,
        findings: list[SecurityFinding],
    ) -> SecurityScanSummary:
        ...
```

默认规则：

```text
critical：
始终阻止远程模型调用。

high：
当 block_remote_on_high_risk=true 时阻止远程调用。

medium：
默认不阻止，但必须脱敏。

low：
默认不阻止，可以脱敏或仅提示。

扫描失败：
当 block_remote_on_scan_failure=true 时阻止远程调用。
```

`passed` 字段含义需要明确。

建议：

```text
passed = 扫描成功且不存在 high 或 critical 风险
```

不要把“扫描成功”与“没有风险”混为同一个字段。
