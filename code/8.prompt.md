检查：

2. CLI 所有主命令是否可发现。

# 四、最终 MVP 主流程

必须验证以下完整流程：

```text
gitpulse init
    ↓
gitpulse doctor
    ↓
gitpulse check
    ↓
gitpulse commit
    ↓
用户选择并保存 Commit 记录
    ↓

    ↓
gitpulse weekly
    ↓
用户处理待确认内容
    ↓

    ↓

    ↓

    ↓

    ↓
```

端到端测试必须验证：

* 每一步生成的数据能被下一步使用

* 飞书失败不会破坏本地周报
* 重复发送得到阻止
* 最终报告来源覆盖率达到要求

# 五、版本信息

实现统一版本来源。

建议：

```text
src/gitpulse/version.py
```

内容示例：

```python
__version__ = "0.1.0"
```

更推荐从包元数据读取：

```python
from importlib.metadata import PackageNotFoundError, version


def get_version() -> str:
    try:
        return version("gitpulse")
    except PackageNotFoundError:
        return "0.0.0.dev0"
```

CLI 支持：

```bash
gitpulse --version
```

输出：

```text
GitPulse 0.1.0
```

要求：

1. 版本号只有一个权威来源。
2. 不在多个文件中手动维护不同版本。
3. README 示例版本与实际版本一致。
4. 发布包版本和 CLI 输出一致。
5. 测试开发模式下可以正确读取版本。
6. 无法读取版本时使用开发版本标识。
7. 不隐藏版本读取异常中的敏感信息。
8. 采用语义化版本规则。


# 十三、诊断结果模型

定义：

```python
from enum import StrEnum

from pydantic import BaseModel, Field


class DiagnosticStatus(StrEnum):
    PASS = "pass"
    WARNING = "warning"
    FAIL = "fail"
    SKIPPED = "skipped"


class DiagnosticItem(BaseModel):
    id: str
    name: str
    status: DiagnosticStatus
    message: str
    suggestion: str | None = None
    metadata: dict[str, str] = Field(default_factory=dict)


class DiagnosticReport(BaseModel):
    status: DiagnosticStatus
    items: list[DiagnosticItem]
    generated_at: str
```

整体状态规则：

* 存在 Fail：整体 Fail
* 没有 Fail 但存在 Warning：整体 Warning
* 全部通过或跳过：整体 Pass

# 三十一、安全回归

# 五十五、验收标准

## 安装

* 能构建 Wheel。
* 能构建 Source Distribution。

* 不依赖源码目录。

## 配置

* 配置向导可以运行。
* 支持用户级和项目级配置。
* 不保存 API Key。
* 不保存飞书 Webhook。
* 修改配置前展示预览。
* 写入失败不破坏原配置。
* Doctor 可以检测配置问题。

## Git 与 Commit

* 能读取暂存区 Diff。
* 能执行安全扫描。
* 能生成 Commit Message。
* 能输出三个候选。
* 能识别明显多主题。
* 高风险内容不进入远程模型。
* 不自动执行 Git Commit。

## 存储与 Worklog

* 数据库可以初始化和升级。
* CommitRecord 可以保存。
* Worklog 可以增删改查。
* 事务失败可以回滚。
* 用户可以备份数据。
* 清理数据必须确认。

## 周报

* 能读取指定日期范围。
* 能聚合相关 Commit。
* 能加入 Worklog。
* 正式内容来源覆盖率为 100%。
* Medium 内容需要确认。
* Low 内容默认排除。
* 可以导出 Markdown、Text 和 JSON。

## 飞书

* 只有 Confirmed 周报可以发送。
* 发送前重新安全扫描。
* 支持文本和静态卡片。
* 支持签名。
* 支持预览。
* 支持用户确认。
* 支持发送记录。
* 支持重复发送保护。
* 网络超时可以标记 Unknown。

## 安全

* API Key 不进入配置。
* Webhook 不进入配置。
* Secret 不进入数据库。
* 日志不记录完整 Diff。
* 日志不记录完整 Prompt。
* 日志不记录完整 Payload。
* 发布包不包含 Secret。
* Demo 不包含真实公司数据。
* Debug 模式仍然脱敏。

## 性能

* Git 本地读取达到目标。
* 普通 Diff 分析达到目标。
* SQLite 查询达到目标。
* 200 个 Commit 可以处理。
* 5000 条记录可以查询。
* 性能报告可重复生成。

## 演示

* Demo 仓库可以一键创建。
* Demo 数据可以一键重置。
* 演示流程可以完整执行。
* 离线 Mock 模式可用。
* Demo 模式不会访问真实 AI。
* Demo 模式不会发送真实飞书消息。
